## Project Overview

Smart Vision Pose Assessment System — an embedded UI prototype on ESP32-P4 for real-time exercise pose evaluation. Displays a USB camera feed, runs YOLO11n-pose inference via ESP-DL on SD card, and renders COCO 17-point skeleton overlays with angle measurements and scoring.

**Target**: ESP32-P4-Function-EV-Board with DSI LCD (EK79007), USB UVC camera  
**Framework**: ESP-IDF v5.5.4, LVGL v9.5.0 (`esp_lvgl_port` v2.8.0)  
**Model**: YOLO26n-pose via ESP-DL (`esp-dl` ^3.3.6)

## Architecture

### Startup flow (`app_main()`)
```
bsp_display_start_with_config() → DSI LCD + LVGL init
  → sdcard_init() → pose_estimator_load_and_print()  (SD card mount + model load)
  → allocate PSRAM: s_fb_display + s_fb_infer (dual buffer)
  → ui_init() → ui_create_main_screen() (LVGL widget tree)
  → xTaskCreatePinnedToCore(pose_inference_task)  (core 1, with esp_task_wdt)
  → cam_start(640,480,15,on_camera_frame)  (camera start)
```

### UI widget tree
```
Screen (#0A0E27, flex column)
  ├── Status bar (46px) — time, mode name, camera status, FPS, icons
  ├── Middle row (flex-grow, flex row)
  │     ├── Left menu (132px) — 俯卧撑/引体向上/仰卧起坐 buttons
  │     ├── Pose stage (flex-grow)
  │     │     ├── camera_container → camera_img (RGB565 preview)
  │     │     └── skeleton_container → lines + dots (COCO 17 pts)
  │     └── Angle panel (174px) — score + 4 angle labels
  ├── Suggestion bar (auto-height) — scrolling guidance text
  ├── Control bar (56px) — 开始观察 button + settings button
  └── Message popup (hidden, centered) — timed auto-hide alerts
```

### Key design decisions
- **Dual PSRAM buffers** — display buffer written only within `bsp_display_lock()` to avoid LVGL tearing; inference buffer written freely and consumed by inference task via notification.
- **C/C++ bridge** — `pose_estimator.hpp` uses `extern "C"` so pure-C `app_main.c` can call C++ ESP-DL functions.
- **Skeleton rendering** — `norm_to_pixel()` maps [-1,1] joint coords to container pixels with aspect-ratio-correct scaling.
- **Chinese font** — hand-picked ~100 CJK chars built into a dedicated 22px font from Deng.ttf.

## Camera Driver Details (`main/camera/camera.c`)

### UVC Camera Pipeline (current — USB UVC mode)

```
cam_start(width, height, fps, cb)
  → query camera format descriptors via USB
  → MJPG preferred, YUY2 fallback
  → UVC stream negotiates selected format
  → callback receives MJPG frame data
  → esp_cache_msync(CLEAN) for HW decoder
  → jpeg_dec_parse_header() + jpeg_dec_process() (HW JPEG decode)
  → esp_cache_msync(INVALIDATE) for CPU
  → on_camera_frame() callback → ui_update_camera_preview()
```

### MJPG Frame Callback Mode
- Callback copies MJPG data to `mjpg_frame_buf` and returns `true` immediately (driver reuses buffer, avoids ISOC transfer errors).
- Processing task polls `frame_ready` flag.
- JPEG decoder configured with `scale` to convert camera's native 1280×1024 → 640×480 output.
- `jpeg_dec_config_t` with `dec_cfg.scale` for downscaling, `block_enable` is incompatible with scale.

### Format Selection Algorithm
1. `select_mjpeg_format()`: scans camera descriptor for MJPG entries, picks highest pixel count ≤ requested size. Caps FPS to 30 (camera's stable rate).
2. `select_yuy2_format()`: fallback to YUY2 if no MJPG match.
3. Selected FPS from camera's `default_interval` (cap to 30fps for reliability).

### Debugging History — USB UVC ISOC Issues

The following were tried and the root cause identified:

| Attempt | Result |
|---------|--------|
| YUY2 640×480 @ 20fps | ISOC frame errors + buffer underflow |
| MJPG 640×480 (default_interval 400fps) | Frames only 8-9KB → JPEG_ERR_NO_MORE_DATA (-3) |
| MJPG 640×480 @ 30fps | Frames 47-52KB but ISOC errors corrupt data → JPEG_ERR_BAD_DATA (-5) |
| `return true` from callback (immediate buffer return) | Eliminated buffer underflow, ISOC errors reduced |
| Separate MJPG buffer from decode buffer | Prevented buffer overlap corruption |
| `esp_cache_msync()` for cache coherency | Fixed cache alignment issues |
| `jpeg_dec_config_t.scale` for output scaling | Needed because camera sends native 1280×1024 inside MJPG |
| Removing `block_enable` (conflicts with `scale`) | Fixed decoder creation failure |
| LVGL test pattern from PSRAM | Confirmed LVGL can display PSRAM-backed images |
| FPS caps: 400→200→120→60→30 | Larger frames but still corrupted by ISOC errors |

**Root cause**: ESP32-P4-Function-EV-Board's USB Host has unreliable ISOC transfers with this particular UVC camera (`LRCP U3-JX02`). The hardware JPEG decoder (`esp_new_jpeg`) cannot tolerate even minor data corruption. Every MJPG frame is truncated or corrupted by ISOC packet loss.

**Camera capabilities (verified via v4l2-ctl on Linux)**:
- Camera model: LRCP U3-JX02
- MJPG 640×480 supports: 400, 200, 120, 60, 30 fps
- YUYV (YUY2) 640×480 supports: 400, 200, 120, 60 fps
- Native sensor resolution: 1280×1024
- MJPG frames at 30fps are ~50KB (adequate for 640×480)

### Future Plan: MIPI-CSI Migration
The board has a MIPI-CSI FPC connector (15-pin, 1.0mm pitch) supporting OV5647 and SC2336 sensors. BSP provides `bsp_camera_start()`.
- Original git commit `67e65f9` has a working V4L2 + MIPI-CSI camera.c
- MIPI-CSI uses `/dev/video0` (ESP_VIDEO_MIPI_CSI_DEVICE_NAME)
- Raw image capture (no JPEG decode needed), eliminates ISOC issues entirely
- Git history shows `9f0c9f5 CSI转UVC调试` as the switch point

## Pose Inference Details

### Inference task (`pose_inference_task` in `app_main.c`)
- Runs on Core 1, priority 5, stack 16384.
- Registered with task watchdog via `esp_task_wdt_add()`.
- Rate-limited to max ~3fps (300ms minimum interval).
- Feeds watchdog via `esp_task_wdt_reset()` at multiple points.

### Demo Mode
- When SD card init fails, `s_demo_mode = true`.
- Generates a standing COCO 17-pose skeleton with subtle arm sway animation.
- No inference call made; `ui_update_skeleton()` called directly.

### Model
- YOLO26n-pose model at `/sdcard/models/yolo26n-pose_esp32p4.espdl`.
- ESP-DL pipeline: `ImagePreprocessor` → `dl::Model::run()` → `yolo11posePostProcessor`.
- Preprocessing: letterbox resize to 640×640, int8 quantization.
- Output: COCO 17 keypoints in [-1, 1] normalized coordinates.

## Memory Layout

| What | Where | Size |
|------|-------|------|
| Model file | SD card | ~6-10 MB |
| `s_fb_display` | PSRAM, 16B-aligned | 640×480×2 = 614 KB |
| `s_fb_infer` | PSRAM, 16B-aligned | 640×480×2 = 614 KB |
| `mjpg_frame_buf` | PSRAM, 64B-aligned | 128 KB |
| `rgb565_buffer` | PSRAM, 64B-aligned | 640×480×2 = 614 KB |
| UVC frame buffers | PSRAM (4 buffers) | 4 × 128 KB = 512 KB |
| UVC URB buffers | Internal SRAM (4 URBs) | 4 × 16 KB = 64 KB |
| SPIFFS partition | Flash | 2 MB |
| Factory app | Flash | 6 MB |

> **2025-07-20**: Reduced UVC URB count (12→4), URB size (64KB→16KB), frame buffers (8→4), frame size (512KB→128KB) to match official `usb_host_uvc` examples. ESP32-P4 DWC2 controller has limited ISOC scheduling depth vs PC xHCI — over-provisioning URBs causes hardware periodic schedule overflow. Saved ~3.5MB PSRAM.
